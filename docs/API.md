## Conventions

- **Base path:** `/api`. JSON in and out, except `POST /api/auth/token`, which takes form data.
- **Authentication:** `Authorization: Bearer <JWT>` from the OAuth2 password grant, with a scope per endpoint.
  - The booking flow is open to **guests**.
  - A held booking's hosted payment page is secured by its secret `session_id`.
  - A booking is secured by the PNR / booking ID plus a passenger's last name.
- **Identifiers:** `USR001`, `PAX001`, `FLT001`, `PAY001`, `BK001`, `CHK001`, `TKT001`, `SSR001`, `WH001`. Payment sessions use `ps_…`.
- **PNR:** 6 characters, never using `0 O 1 I`. It is only disclosed together with a passenger's last name.
- **Datetimes:** ISO-8601 with an offset. Flight times are in the airport's local time; hold expiry and system times are UTC.
- **Money:** fares are in USD (`base_amount`). Bookings and payments carry `currency` and the amount charged.

### Errors
Errors always have the shape `{ "detail": "…" }`.

| Status | Meaning |
|---|---|
| 400 | Business-rule violation or bad input |
| 401 | Token missing, invalid or expired |
| 402 | Card declined (hosted payment) |
| 403 | Token lacks a scope, or you are not the owner |
| 404 | Not found (also used for other users' records and PNR/last-name mismatches) |
| 409 | Conflict: no seats, aircraft busy, already checked in, session not payable |
| 422 | Request schema validation failed |

## End-to-end flow (as a guest, round trip with a connection)

```bash
API=http://localhost:8000/api

# 1. Search (2 adults, 1 infant) — prices per passenger type and baggage are included
curl "$API/itineraries/search?origin=DEL&destination=LHR&date=2026-09-25&return_date=2026-09-28&adults=2&infants=1"

# 2. Passengers
curl -X POST $API/passengers -H 'Content-Type: application/json' \
  -d '{"first_name":"Ravi","last_name":"Kumar","date_of_birth":"1985-02-02","gender":"M"}'

# 3. Hold the booking → PNR + payment link (seats held 30 min)
curl -X POST $API/bookings -H 'Content-Type: application/json' -d '{
  "outbound_flight_ids":["FLT0102","FLT0201"], "return_flight_ids":["FLT0906","FLT1007"],
  "class_id":"ECONOMY", "passenger_ids":["PAX001","PAX002","PAX003"],
  "currency":"INR", "client_reference_id":"chat-42", "success_url":"http://localhost:5173/booking?last_name=Kumar&paid=1" }'
#   → booking.status = PENDING, booking.pnr, payment.payment_url = http://localhost:5173/pay/ps_…

# 4. Pay: open payment_url in a browser, or call the gateway API directly with a test card
curl -X POST $API/payment-sessions/ps_…/pay -H 'Content-Type: application/json' \
  -d '{"card_number":"4111111111111111","expiry":"1230","cvv":"123","holder_name":"RAVI KUMAR"}'
#   → 200 COMPLETED (booking CONFIRMED, webhooks sent) | 402 declined (retry allowed)

# 5. Retrieve
curl "$API/bookings/pnr/ZJDTKL?last_name=Kumar"

# 6. Check in (48 h to 4 h before each flight), one flight at a time
curl -X POST $API/checkins/validate -H 'Content-Type: application/json' -d '{"pnr":"ZJDTKL","last_name":"Kumar"}'
curl -X POST $API/checkins -H 'Content-Type: application/json' \
  -d '{"pnr":"ZJDTKL","last_name":"Kumar","flight_ids":["FLT0102"],"passenger_ids":["PAX001","PAX003"]}'

# 7. Boarding pass
curl "$API/tickets/TKT001?last_name=Kumar"
```

As a member, add `-H "Authorization: Bearer $TOKEN"`. The passengers and the booking then belong to the member, and
tier benefits apply.

## Endpoints

"public" means no token is needed. "guest or `scope`" means the endpoint works without a token, or with a token that has that scope.

### Authentication
| Method | Path | Scope | Description |
|---|---|---|---|
| POST | `/auth/token` | public | OAuth2 password grant (form: `username`, `password`, `scope?`) |
| POST | `/auth/register` | public | Create a customer account (Bronze) |
| GET | `/auth/me` | `profile` | Profile, token scopes, allowed scopes |

### Search, flights, fares, policies
| Method | Path | Scope | Description |
|---|---|---|---|
| GET | `/itineraries/search` | public | `origin`, `destination`, `date`, `return_date?`, `cabin_class?`, `adults`, `children`, `infants`. Returns fares per type, party total, baggage and phase |
| GET | `/flights/search` | public | Direct flights only |
| GET | `/flights` · `/flights/{id}` | public | Flight records and one flight (with `phase`) |
| GET | `/flights/schedules` | `admin` | Paged admin view |
| POST | `/flights/schedules` | `flights:write` | Create a flight (rotation rule applies) |
| PUT | `/flights/schedules/{id}` | `flights:write` | Retime, re-assign, renumber, change status |
| GET | `/fares/flight/{id}` | public | Fares per cabin, with child and infant prices |
| GET | `/fares/ssr/{type}?tier_id=` | public | SSR price |
| GET | `/classes` · `/classes/available` | public | Cabins |
| GET | `/baggage/allowances` | public | Full baggage allowance table |
| GET | `/policies` · `/policies/{slug}` | public | Policy documents (Markdown) |
| GET | `/currencies` · `/currencies/detect` | public | Currencies and rates; suggested currency |

### Passengers and bookings
| Method | Path | Scope | Description |
|---|---|---|---|
| GET | `/passengers` · `/passengers/{id}` | `bookings:read` | Own passengers (admin: all) |
| POST | `/passengers` | guest or `passengers:write` | Add a passenger |
| PUT · DELETE | `/passengers/{id}` | `passengers:write` | Manage own passengers |
| POST | `/bookings` | guest or `bookings:write` | **Hold** a booking → `{booking, payment}` with `payment_url` |
| POST | `/bookings/{id}/payment-session?last_name=` | guest or `bookings:write` | New payment link for a PENDING booking |
| GET | `/bookings` | `bookings:read` | Own bookings (admin: all; filters `user_id`, `status`, `pnr`) |
| GET | `/bookings/pnr/{pnr}?last_name=` | guest or `bookings:read` | **Last name required** |
| GET | `/bookings/{id}?last_name=` | guest or `bookings:read` | Last name required unless you are the owner or an admin |
| PUT | `/bookings/{id}?last_name=` | guest or `bookings:write` | Contact details |
| POST | `/bookings/{id}/change?last_name=` | guest or `bookings:write` | `{direction, new_flight_ids}` — more than 24 h before, within 60 days |
| POST | `/bookings/{id}/cancel?last_name=` | guest or `bookings:write` | Cancel a hold or a booking (refund if paid) |
| GET | `/bookings/{id}/history?last_name=` | guest or `bookings:read` | Audit trail |
| DELETE | `/bookings/{id}` | `admin` | Permanently delete a booking |

### Payments and checkout
| Method | Path | Scope | Description |
|---|---|---|---|
| GET | `/payment-sessions/{session_id}` | public (secret id) | Data for the hosted page |
| POST | `/payment-sessions/{session_id}/pay` | public (secret id) | Pay with a test card → 200, 402 or 409 |
| GET | `/payments` · `/payments/{id}` · `/payments/{id}/attempts` | `bookings:read` | Own payments and attempts (admin: all) |

### Check-in and tickets
| Method | Path | Scope | Description |
|---|---|---|---|
| POST | `/checkins/validate` | guest or `checkin:write` | `{pnr, last_name}` → per-segment window, phase and passenger eligibility |
| POST | `/checkins` | guest or `checkin:write` | `{pnr, last_name, flight_ids?, passenger_ids?}` → check-ins and boarding passes |
| GET · PUT | `/checkins/{id}` | `bookings:read` / `checkin:write` | Seat change or offload (owner / admin) |
| GET | `/checkins` | `admin` | All check-ins |
| GET | `/tickets/{id}?last_name=` · `/tickets/{id}/boarding-pass` | guest or `bookings:read` | Boarding pass (with baggage and phase) |
| GET · POST · DELETE | `/tickets[/{id}]` | `admin` / `tickets:write` | Manual ticketing |

### Special service requests
| Method | Path | Scope | Description |
|---|---|---|---|
| GET | `/ssrs/catalog` | public | SSR types |
| GET | `/ssrs` · `/ssrs/{id}` · `/ssrs/available` | `ssr:read` | Own SSRs and eligibility |
| POST | `/ssrs` | `ssr:write` + `ssr:<TYPE>` | Create an SSR on a segment (confirmed member bookings) |
| DELETE | `/ssrs/{id}` | `ssr:write` | Cancel an SSR |

### Reference data and admin
| Method | Path | Scope | Description |
|---|---|---|---|
| GET | `/airports`, `/routes`, `/routes/valid`, `/routes/sources`, `/routes/destinations`, `/tiers` | public | Reference data |
| GET | `/users` · `/users/{id}` | `admin` / self | Users |
| GET | `/aircrafts`, `/aircrafts/available?route_id=&departure_time=` | `admin` | Fleet and free aircraft |
| GET | `/admin/summary` | `admin` | Dashboard counts |
| POST | `/admin/schedules/generate` | `flights:write` | Generate 3–4 validated flights per route per day |
| POST | `/admin/holds/expire` | `admin` | Expire unpaid holds now (this also runs every minute) |
| GET · POST · DELETE | `/admin/webhooks[/{id}]` | `admin` | Webhook subscriptions (the create response includes the signing secret) |
| GET | `/admin/webhooks/deliveries` | `admin` | Delivery log |
| GET | `/health` | public | Health check |

### Webhook events
`booking.held`, `payment.succeeded`, `payment.failed`, `booking.confirmed`, `booking.expired`, `booking.cancelled`.
Each delivery carries the header `Udaan-Signature: t=<unix>,v1=<HMAC-SHA256(secret, "<t>.<raw body>")>`. See the
[integration guide](integration/payment-links-and-agents.md) for the payload and verification code.
